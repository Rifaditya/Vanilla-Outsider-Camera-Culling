# 👑 Boss & Blacklist Immunity (Minecraft 26.3)

To ensure gameplay fairness and combat awareness, critical threats and companion animals must never disappear behind walls or be affected by aggressive culling algorithms.

**Camera Culling** incorporates dynamic boss identification and a two-tier immunity blacklist.

---

## 🐲 Dynamic Boss & Mini-Boss Detection

Camera Culling evaluates boss immunity through two distinct mechanisms:

### 1. Dynamic Health Thresholding
Any `LivingEntity` whose `getMaxHealth()` meets or exceeds the configured thresholds is granted unconditional immunity:
* `maxHealth >= 150.0` $\implies$ Major Boss (Ender Dragon, Wither, Warden).
* `maxHealth >= 50.0` $\implies$ Mini-Boss (Elder Guardian, Ravager, Iron Golem, Piglin Brute, Breeze, modded champions).

### 2. Registry & Identifier Keyword Heuristics
Entities with names matching any of the following substrings are automatically identified as bosses:
```text
dragon, wither, warden, elder_guardian, ravager, evoker, iron_golem, 
piglin_brute, breeze, boss, miniboss, mini_boss, titan, leviathan, 
harbinger, monarch, behemoth, champion, elite, brute
```

## 🛡️ Two-Tier Immunity Blacklist System

```text
Immunity Resolution
├── Local Player / Vehicle / Mount ──► 100% Rendered
├── Glowing Effect Active ──────────► 100% Rendered
├── Boss or Mini-Boss Detected ─────► 100% Rendered
├── Client Blacklist Match ─────────► 100% Rendered
└── Server Admin Blacklist Match ───► 100% Rendered
```

### 1. Client Personal Blacklist
Players can whitelist specific companion entities locally using in-game commands:
```sql
/cameraculling blacklist add minecraft:wolf
/cameraculling blacklist add minecraft:allay
/cameraculling blacklist add minecraft:cat
```

### 2. Server Admin Blacklist
Server operators can specify global entity immunities in `config/camera-culling-server.json` or via `/cameraculling serverblacklist add <id>`. All connected clients will automatically honor the server-enforced immunity list.
